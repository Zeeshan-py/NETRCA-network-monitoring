# Phase 8 report — anomaly detection

The original seven `Instruction/` specifications, current Phase 1–7 code and reports, actual migrations, dependencies, API conventions, and Git status were inspected first. The only prior working-tree change was `.gitignore`; it remains untouched. The prior Phase 7 commit is local and still one commit ahead of `origin/main` because the earlier GitHub push could not connect.

Phase 8 adds validated analysis of stored Phase 6 metrics or caller-provided inline observations. Thresholds cover latency, packet loss, availability, interface/link down state, and error-counter deltas. A robust median/MAD baseline can find smaller relative latency/loss spikes when enough distinct history exists. A bounded Isolation Forest path is present for sufficiently varied history when scikit-learn is installed; it does not fit the candidate or fabricate training data. Results explain method, reason, source measurement, supporting values, sample count, score interpretation, and severity. Repeated observations are deduplicated. Local-only detection works without a database; only findings from confirmed stored metric IDs are eligible for optional persistence in the existing `public.anomalies` table. No migration or remote schema modification was made.
