# Phase 7 report — controlled fault injection

Implemented four bounded fault types against the fixed Mininet lab: interface down, link down, host-port packet loss, and host-port latency. The controller allows one active fault, records captured pre-state, supports explicit recover/cancel/reset, restores on expiry and lab shutdown, and retains failed restorations for retry. Fault operations use the Phase 3 single-worker manager and owned Mininet instance. Loopback and local-control gates match the existing simulator API. The setting `NETRCA_FAULT_INJECTION_ENABLED` defaults to `false`.

The existing `public.fault_injections` table is used for best-effort lifecycle persistence when an active stored device or exact stored link endpoints/interfaces match the live target. No migration or remote schema change was made. In-process records remain authoritative for restoration when the database is unavailable or unmapped. Phase 5 observation and Phase 6 evidence logic were left unchanged; the real test observes a down interface/link through a monitoring snapshot and 100% packet loss through a probe. Fault application does not create fabricated evidence.

Limits: the service is for one local development process, not a durable distributed scheduler. Abrupt process death can leave an operating-system change until the Mininet instance is stopped; inspect and stop the owned lab before restarting. An unmapped live target is still safely controlled but has no database row. A failed restoration remains active and retriable; after ten automatic retries, an operator must recover it explicitly. Existing foreign qdiscs are refused. Bandwidth restriction was intentionally not enabled. Database reachability and real persisted transitions remain to be verified when the pooler is accessible.
